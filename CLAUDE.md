# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

JournalAI is a two-package repo (no root `package.json` or workspace tooling, so run commands from inside each package):

- `backend/` is a NestJS 12 API with Prisma 7 (Postgres via `@prisma/adapter-pg`), Redis, and CQRS.
- `mobile/` is an Expo SDK 58 / React Native app using Expo Router.

The product idea, as the Prisma schema shows: during the day a user captures **Snippets** (text, voice, or share-sheet, synced from the device). Each calendar day is a **DailySession** that moves through `open → interviewing → drafted → finalized`. The AI asks follow-up **Questions**, writes an **Entry** draft (`aiDraft`), and the user edits it into the final `body`. A **StyleProfile** (sample entries plus notes) steers the AI's writing voice. Most feature controllers are still stubs that only have route comments (e.g. `days.controller.ts`: `GET /days/:date`, `GET /days/:date/interview`, `POST /days/:date/draft`, `POST /days/:date/finalize`).

## Backend commands (`cd backend`)

```bash
npm run dev            # nest start --watch
npm run build          # nest build -> dist/
npm run typecheck      # tsc --noEmit
npm run lint           # eslint --fix
npm run format         # prettier
npm test               # jest, rootDir=src, matches *.spec.ts
npx jest src/path/to/file.spec.ts   # single test file
npx jest -t "test name"             # single test by name
npm run db:generate    # prisma generate -> src/generated/prisma
npm run db:migrate     # prisma migrate dev
```

The `test/` directory does not exist yet, so `test:e2e` won't run until it is created.

The Prisma CLI config is `backend/prisma7.config.ts`. It reads `DATABASE_URL` from `.env`, and `schema.prisma` has no `url` in its datasource. Copy `.env.example` to `.env` before starting the app.

## Backend architecture

- **Bootstrap (`src/main.ts`, `src/config/index.ts`).** Sets the global prefix `/api`. Sessions are `express-session` stored in Redis via `connect-redis`, and `main.ts` creates its own client from the `redis` package. Also sets up CORS (extra origins and headers come from the JSON-array env vars `CORS_ORIGIN`, `CORS_ALLOWED_HEADERS`, `CORS_EXPOSED_HEADERS`), a strict global `ValidationPipe` (`whitelist` + `forbidNonWhitelisted`, so every accepted DTO field needs a class-validator decorator), and global Prisma exception filters. Swagger is served at `/api/swagger` only when `NODE_ENV=development`.
- **Config (`src/services/configService/`).** A custom `ConfigService` validates `process.env` against a Zod schema (`config.schema.ts`) at startup and exposes typed `get(key)`, which throws if the value is missing. When you add an env var, add it to the schema and to `.env.example`. `PrismaService` reads `DATABASE_URL` straight from `process.env`.
- **Global services (`src/services/globalservices.module.ts`).** A `@Global()` module that provides `AppLogger`, `ConfigService`, `EmailService` (nodemailer), `PrismaService`, and `RedisService` (`ioredis`, a separate client from the session one). Inject these anywhere without importing a module.
- **Features (`src/features/<name>/`).** Each feature has a `<name>.module.ts` and a `<name>.controller.ts`, and the module is registered in `app.module.ts`. Controllers inject `CommandBus`/`QueryBus` from `@nestjs/cqrs`. Business logic is meant to live in command/query handlers registered as module providers, not in services called directly from controllers.
- **Auth.** `AuthGuard` (`src/guards/auth.guard.ts`) checks `req.session.isAuthenticated` and skips anything marked with `@Public()` (`src/decorators/public.decorator.ts`). Session fields are typed in `src/types.d.ts`. The guard is not registered globally yet.
- **Prisma.** The client is generated into `src/generated/prisma` (gitignored) and imported as `@prisma/generated` (tsconfig path). `@src/*` also maps to `src/*`. Re-run `npm run db:generate` after every schema change. Every model has a `userId` relation to `User`, and tables use snake_case names through `@@map`.

## Mobile (`cd mobile`)

Read `mobile/AGENTS.md` before touching Expo code. The main points:

- Expo APIs change every SDK. Check the `expo` major version in `package.json` (currently 58) and consult `https://docs.expo.dev/versions/v58.0.0/` or `https://docs.expo.dev/llms.txt` rather than relying on memory.
- Add dependencies with `npx expo install <pkg>`, not `npm install`.
- Before calling a task done, run `npx expo lint` and `npx tsc --noEmit`. Start the app with `npx expo start`.
- Routes live in `src/app/` and use Expo Router file-based routing (every file is a screen, and `_layout.tsx` files define navigators). Non-route code goes in `src/components`, `src/hooks`, and `src/constants`, imported through the `@/` alias. Platform variants use a `.web.tsx` suffix.
- `ios/` and `android/` are generated by Continuous Native Generation. Never edit them by hand; configure native behavior in `app.json` and config plugins instead.
- Typed routes and the React Compiler are enabled in `app.json`.

The app is still the Expo starter template and does not call the backend yet.
